# Stages Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the dated 8-week task calendar with per-skill Skill tracks made of fixed Stages, each holding a few Goals and a small Habit list, with score Gates the teacher confirms.

**Architecture:** Stage definitions (names, order, Gates) are fixed in code in `src/lib/stages.ts`. Goals and Habits are teacher-editable rows keyed by `(skill, stage)`. All Gate, streak and "next Full test" logic is pure functions in `src/lib/stages.ts` and `src/lib/stats.ts`, unit-tested with Vitest; pages only render what those functions return. The next Full test is *derived* from recorded results (last Full test + 56 days), not stored as a row.

> **As built (2026-10-21):** the work shipped as tickets 01–07 in `.scratch/stages/issues/`, so some names below differ. Migrations are `006_tracks_goals.sql` to `010_remove_calendar.sql` instead of one `006_stages.sql`. Habit week count and streak live in `src/lib/habits.ts`. The Goal/Habit dialog is `StageItemForm.tsx`, the Habit row is `HabitItem.tsx` (no `HabitChecklist`), and the last-Stage Gate label is "Last Stage".

**Tech Stack:** React 19 + TypeScript + Vite, TanStack Query, Supabase (Postgres + RLS), Tailwind, Recharts, Vitest (new).

**Spec:** `GLOSSARY.md` (terms and Stage definitions) and `docs/adr/0001-stages-replace-dated-weekly-plan.md`. Decisions from the design session are restated in Global Constraints.

## Global Constraints

- Skills in the app: `Listening`, `Reading`, `Writing`. Speaking is not in the app.
- Use glossary terms exactly in code and UI copy: Stage, Gate, Goal, Habit, Full test, Section (Listening), Passage (Reading), Question type, Lilie technique. Never "mission", "task", "Part", "homework" in new UI copy.
- Stage order. Listening: Foundation → Diagnosis → Focus → Exam-ready. Reading: Foundation → Diagnosis → Focus → Passage 3. Writing: Templates → Practice.
- Reading starts after Listening leaves Foundation. Writing starts after Reading leaves Foundation. The teacher confirms every start and advance.
- Gates: Foundation and Templates = all Goals of the Stage done. Diagnosis = all Goals done **and** a Full test of that skill recorded on or after the Stage's start date. Focus = a Full test with band ≥ 7.0 recorded on or after the Stage's start date (one is enough). Last Stages have no Gate.
- A met Gate only *suggests* advancing. The teacher can advance whether or not the Gate is met.
- Next Full test is due 56 days after the latest Full test of that skill. It is shown only for Listening and Reading tracks in Focus or later.
- Habit rhythm is `perWeek` 1–7; 7 means daily. Weeks run Monday–Sunday. A streak is shown only for daily Habits.
- The teacher edits Goals, Habits and the Course end date. The student only ticks Goals and Habits. Both can record test results (the teacher records Writing marks).
- Course seed: start `2026-10-19`, end `2027-04-19`.
- Dates are `yyyy-MM-dd` strings built with `toISO` from `src/lib/utils.ts`.

## Review Focus

- A Full test taken *before* the track entered Focus (e.g. a lucky diagnostic 7.0) must not open the Focus Gate. Pinned in Task 1 (`gateStatus ignores results before enteredOn`).
- Weekly Habit count across a week boundary: a Sunday tick counts in the week that started the Monday before, and a Monday tick starts a new week. Pinned in Task 2 (`habitWeekCount uses Monday-Sunday weeks`).
- Ties for the weakest Listening Section must pick the lowest Section number (order 1→4). A Reading result with no wrong answers has no weak area. Pinned in Task 2 (`weakestArea` tests).
- A Course end date already in the past shows 0 weeks left, never a negative number. Pinned in Task 2 (`weeksLeft clamps at 0`).
- Writing results have no correct/total, and the Progress table must not render `undefined/undefined`. Pinned in Task 7 Step 2 (render `—`).

  export interface Course { startDate: string; endDate: string }
  export interface Track { skill: Skill; stage: StageKey | null; enteredOn: string | null } // stage null = not started
  export interface Goal { id: string; skill: Skill; stage: StageKey; title: string; description: string; dueDate?: string; sortOrder: number }

  }

- Produces (in `src/lib/stages.ts`):
  ```ts
  export const QUESTION_TYPES = ['Matching headings', 'Matching information', 'Matching features', 'Matching sentence endings',
    'True / False / Not Given', 'Yes / No / Not Given', 'Multiple choice', 'Sentence completion',
    'Summary, note, table or flow-chart completion', 'Diagram label completion', 'Short-answer questions'] as const
  export type Gate = { kind: 'goals' } | { kind: 'goals_and_test' } | { kind: 'band'; min: number } | { kind: 'none' }
  export interface StageDef { key: StageKey; name: string; gate: Gate }
  export const TRACKS: Record<Skill, { stages: StageDef[]; startsAfter?: { skill: Skill; stage: StageKey } }>
  export function stageDef(skill: Skill, key: StageKey): StageDef
  export function nextStage(skill: Skill, key: StageKey): StageKey | null
  export function canStart(skill: Skill, tracks: Track[]): boolean
  export function gateStatus(track: Track, goals: Goal[], doneGoalIds: Set<string>, results: TestResult[]): { met: boolean; label: string }
  ```
  Stage names: `Foundation`, `Diagnosis`, `Focus`, `Exam-ready`, `Passage 3`, `Templates`, `Practice`. Focus gate is `{ kind: 'band', min: 7 }`. `startsAfter` for Reading is `{ skill: 'Listening', stage: 'foundation' }` and for Writing `{ skill: 'Reading', stage: 'foundation' }`. It means the other track's current Stage is *after* that one. `gateStatus` considers only the Goals with `goal.skill === track.skill && goal.stage === track.stage`, and only results with the same skill and `date >= track.enteredOn`.
